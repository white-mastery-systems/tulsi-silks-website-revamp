1. Overview & goals

Migrate the category page from a load-all-products, filter-in-browser model to a server-driven catalog using two APIs:

APIPurpose
POST …/product/available_filters Filter groups + category price_range
POST …/product/list_v4 Paginated products, category_details, catalog_page_segments

Goals

  • Performance: Paginate 8,000+ products server-side (Core Web Vitals)
  • SEO: One H1, canonical URLs, structured data, fast first paint
  • UX: Stable filters, clear counts, mobile-friendly drawer, trust content below grid
  • Maintainability: CMS-driven below-fold segments via catalog_page_segments
Scope: Standard category routes only (/category/kanjivaram-silk-sarees). Special routes (/all-products, /new-arrivals, etc.) stay on existing APIs.

3. Target architecture

Route: /category/:category_id │ ├─► POST available_filters { category_id } │ └─► tag_list sidebar + price_range (slider bounds) │ └─► POST list_v4 { category_id, page, limit, sort_by, min/max_price, filters } ├─► category_details → banner, H1, navigationList, SEO ├─► list + total → product grid (one page) └─► catalog_page_segments → below-fold CMS blocks

Load sequence

  1. Route param resolves category_id
  2. loadAvailableFilters() — filter UI + price bounds
  3. fetchProductList() — default page 1, no filters
  4. User changes filter / sort / price / page → only list_v4 refetches

4. API contracts

4a) available_filters

POST /store_details/product/available_filters?store_id={store_id}
Body: { "category_id": "kanjivaram-silk-sarees" }

Response: { status, available_filters[], price_range: { min, max } }

4b) list_v4

POST /store_details/product/list_v4?store_id={store_id}
Body: {
  "category_id": "kanjivaram-silk-sarees",
  "page": 1,
  "limit": 24,
  "min_price": 11160,
  "max_price": 179500,
  "sort_by": "price_asc",
  "filters": {
    "5d3057b12d12374382fc07a0": ["Green"]
  }
}

Response: {
  status, category_details, catalog_page_segments[],
  list[], total, page, limit, total_pages
}

7. SEO best practices

On-page

  • One visible H1 — seo_details.h1_tag; no hidden duplicate
  • Title & meta — from page_title, meta_desc via setSiteMetaData()
  • Clean URL — /category/kanjivaram-silk-sarees

Faceted navigation

URL typeIndexing
Base categoryindex, follow — canonical = self
Filtered (?body_colour=green)Canonical → base URL; consider noindex for deep combos
Pagination page 2+noindex, follow or rel next/prev

Structured data

  • BreadcrumbList — dynamic hierarchy
  • CollectionPage + ItemList — page 1 products only; add numberOfItems: product_count
  • FAQPage — from category_details.faqs
  • Keep existing LocalBusiness / Organization graph

Performance (CWV)

  • Server pagination — primary LCP win
  • Lazy-load product images (appImgLazyLoad)
  • Preload category banner (LCP candidate)
  • Target LCP < 2.5s, INP < 200ms

8. UX best practices

Filters

  • Stable options from API — never shrink after selection
  • Primary filters first: Material, Body Colour, Design, Occasion
  • Body Colour as swatches; others as chips
  • Active chips above grid + Clear all
  • Mobile: full-screen drawer, badge count on Filters button
  • Show total after apply — "3 products" vs "8,690 products"
  • Debounce price slider ~300ms
  • Reset to page 1 on any filter/sort change

navigationList

  • Quick discovery — links to sub-categories, not query filters
  • Replace hardcoded activeSlideIndex==3 with data-driven layout type

catalog_page_segments

TypeUser job
icon_card_grid"I don't know what to search" (occasion shortcuts)
founder_faq_grid"Is this authentic?"
content_checklist_split"Why does it cost this much?"
ctaWhatsApp / Browse collection

Back from product

Extend category_page_attr to restore: page, filters, sort, scroll position, segments.
