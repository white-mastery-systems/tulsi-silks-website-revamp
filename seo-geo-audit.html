🔍 Executive Summary

Tulsi Silks has a partially functioning Angular Universal SSR implementation but is critically undermined by a structural flaw: all structured data (JSON-LD), meta tags, canonical URLs, and Open Graph tags are populated exclusively via client-side JavaScript — they are absent from the initial server-rendered HTML response.

This single failure makes the site largely invisible to AI crawlers (GPTBot, ClaudeBot, PerplexityBot, Google-Extended), which either do not execute JavaScript or only partially render it. The site has excellent content depth, a 30-year brand story, and capable engineering — but GEO readiness is currently 2.5/10.

The good news: 4 of the top 10 issues are 1-hour fixes that would immediately raise AI visibility from 2.3 to approximately 5–6/10.

Crawlability Analysis

🚨
CRITICAL: Homepage JSON-LD is browser-only (line 656, common.service.ts)

The applyHomePageJsonLd() method starts with if (!isPlatformBrowser(...)) return; — this means ALL homepage structured data is stripped from the SSR HTML response. AI crawlers see zero schema.

🚨
CRITICAL: index.html has empty meta tags

Meta description, OG tags, and canonical link all have content="" and href="" in the initial HTML. These are only populated after JavaScript API calls complete.

🚨
CRITICAL: Blog publisher logo uses localStorage (SSR crash)

localStorage.getItem('random_num') returns null on the server, producing an invalid publisher logo URL in every BlogPosting schema.

Top 10 Issues Preventing AI Visibility

  1. JSON-LD never reaches SSR HTML. isPlatformBrowser guard in applyHomePageJsonLd() strips ALL structured data from the server response. This is the single highest-impact fix available.
  2. Meta description, OG tags, and canonical are empty strings in index.html. AI crawlers reading raw HTML see no description, no title context, and no canonical URL.
  3. Product content is entirely JS-dependent. All product names, descriptions, prices, and availability require JavaScript execution. Non-JS crawlers see an empty product page.
  4. No citable founder/expert profile pages. Tulsi Silks cannot appear in AI answers about "saree experts" or "Kanjivaram specialists" because no SSR-available content establishes this expertise.
  5. Blog publisher logo uses localStorage. This crashes BlogPosting schema on SSR, producing invalid publisher data for the blog — the site's most valuable citation content.
  6. Category menu links 404. Menu links like /kanjivaram-silk-sarees return 404 errors (correct path: /category/kanjivaram-silk-sarees). Broken internal links destroy crawl graph integrity.
  7. No Speakable schema. Google AI Overviews, Gemini, and voice assistants cannot identify which content zones are authoritative or citable without SpeakableSpecification.
  8. Sitemap: all priorities 1.0. No crawl budget differentiation. 900+ URLs all equal — search engines cannot distinguish homepage from checkout page.
  9. Author bios too brief for E-E-A-T. "Decades of experience in sarees and textiles" is one vague sentence. Specific, demonstrable expertise is required for AI citation eligibility.
  10. robots meta tag missing "follow". content="index" without "follow" may prevent link equity flow through the site's extensive internal linking structure.

  1. Add static JSON-LD to index.html — Organization + WebSite schema visible to every crawler immediately. Zero API dependency. ~30 minutes work.
  2. Remove isPlatformBrowser from applyHomePageJsonLd() — One-line deletion in common.service.ts:657 enabling homepage schema in SSR HTML.
  3. Fix index.html meta description — Change content="" to a 150-character description of Tulsi Silks. ~5 minutes.
